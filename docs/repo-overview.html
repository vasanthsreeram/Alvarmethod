What this is

A skills pack, not an app. Five SKILL.md files that drop into the skill directory of Claude Code, Codex, Grok, Pi, OpenCode, or anything else that reads the Agent Skills spec. Once installed, the agent stops behaving like a course and starts behaving like one tutor who already knows what you hold and what you don't.

The whole pack is 21 tracked files, 4 commits, and no runtime. The installer is a shell script that copies directories.

The short version: many-to-many learning leaks effort in both directions. The fix is one interface, many sources — the teacher aggregates the sources, and trust is engineered through verification rather than accumulated over years.

Why one-to-one

Two leaks the method names explicitly:

DirectionWhat it wastes
One outlet → many students A book, course, or video made for a crowd cannot be optimal for one mind. Optimal teaching depends on the learner's current understanding — the arc from here to the goal, and each explanation on the way.
One student → many outlets Switching styles, notations, reliability, and interfaces costs effort that never reaches the material. The deeper cost is trust: the brain hedges on an unfamiliar source and won't fully commit the fact until it feels proven.

So the path must sit at the edge of understanding — never reteaching what is already held, never presenting what cannot yet be taken in. And "only one teacher means only one perspective" confuses source with interface: the teacher aggregates many sources and delivers them through one trusted front door. Perspectives are not lost.

The two principles

  • Optimized teaching — fitted to this mind, at the edge.
  • Optimized allocation of mental resources — concentrate struggle in the material. The system absorbs logistics: order, sources, verification, "what next," logging, diagrams. Difficulty is never removed; struggle is maximized in the thing being learned.

The loop

  1. 01 Probe — measure the edge Graded multiple choice through the harness picker, 1–3 questions per turn, always including I don't know. Start wide, then binary-search every strand the lesson will depend on. → .alvar/maps/<slug>.md
  2. 02 Plan — reason how to teach this mind this goal Build a dependency DAG where each node is one reasoning step, not a chapter. Start from known, path through edge, never start in unknown with no ramp. The graph is shown before teaching. → .alvar/sessions/<date>-<slug>.md
  3. 03 Teach — one node per turn One reasoning step, then stop. Never dump the whole graph in one message — that is named in the pack as the ChatGPT failure mode. A picture gets made only when it would lock the idea. → .alvar/visuals/<slug>-<n>.svg
  4. 04 Quiz — lock the step in Three reasons: the learner cannot gaslight themselves, the teacher stays calibrated, and applying the idea is how it locks. Advance only on lock-in.

On a miss — the walk stays on the node, or inserts a prerequisite and rejoins. The graph is frozen until a quiz failure forces a new node into it.

Phase order is not decorative. process.md says explicitly: do not skip phases unless the learner already has a fresh map for this exact goal.

Skills

teach

full loop

The whole method: probe → plan → one-step teaching with lock-in quizzes. Reads four references before the first question.

triggers /teach · teach me · tutor me · walk me through

probe

map only

Diagnose without teaching. Labels every dependency strand known, edge, unknown, or blocked, and stops when the lesson's dependencies are labeled — not when "enough questions" were asked.

triggers /probe · quiz me · pretest · find the edge

learn-profile

setup

Interviews the learner across six clusters — solid ground, goal, pace, struggle, voice, artifacts — and writes the file the teacher reads every session.

triggers /learn-profile · how I learn · teaching style

learn-visual

one picture

Makes a teaching diagram for one idea, then looks at the file and fixes it until the picture actually shows the claim. Stop after a clean pass, not the first draft.

triggers /learn-visual · diagram · figure · sketch

learn-verify

trust

Fact-checks one claim in one falsifiable sentence and returns a verdict — confirmed, qualified, contradicted, or unknown. No invented papers, quotes, or page numbers.

triggers /learn-verify · fact-check · is this true

If the specialist skills aren't installed, teach follows the same protocols inline — the loop still works with one skill present.

Install

Preferred — the open skills CLI

# every detected agent, globally, no prompts
npx skills add vasanthsreeram/Alvarmethod -g --all

# list what's in the pack
npx skills add vasanthsreeram/Alvarmethod --list

# one skill
npx skills add vasanthsreeram/Alvarmethod --skill teach -g -y

No extra CLI

npx github:vasanthsreeram/Alvarmethod
npx github:vasanthsreeram/Alvarmethod --list

Clone and run the script

git clone https://github.com/vasanthsreeram/Alvarmethod.git
cd Alvarmethod
./install.sh          # all known agent dirs
./install.sh --project
./install.sh --uninstall

install.sh flags: --project, --list, --uninstall, and filters --agents --claude --grok --pi --opencode --codex. With no filter, all of them are used. bin/alvarmethod.js is just a Node shim that shells out to the same script.

Rules the pack enforces

Teaching

  • One reasoning step per turn. Stop. Quiz that step. Advance only on lock-in.
  • Show the mermaid plan before teaching. Never skip the graph.
  • Don't reteach known. Don't start in unknown with no ramp.
  • Never dump the whole explanation in one message.
  • Don't invent citations — verify, or mark the uncertainty.
  • When the learner interrupts, answer the question. Don't "just finish the slide."

Quiz UI — the rule with the longest section

Every probe and lock-in quiz must call the harness's interactive question tool. Pasting A/B/C/D into the chat is the failure this pack is most explicit about. The correct option is never marked (Recommended) and never deliberately placed first — that leaks the answer.

No matching tool? Say which one is missing and stop. There is no markdown fallback.

Learner files

All session state lives in the learner's working directory, never in this repo. .alvar/ is created on first use and is gitignored by default: 

.alvar/
  LEARNER.md                 # how this mind wants to be taught
  maps/<slug>.md             # probe results for one goal
  sessions/<date>-<slug>.md  # plan + steps + quizzes
  visuals/<slug>-<n>.svg     # diagrams from learn-visual

LEARNER.md is read at the start of every teach session and controls voice and density, how the learner wants to struggle, what they already treat as solid, and whether they want visuals, mermaid, LaTeX, or a long markdown log. The session files are the persistence layer — the portable stand-in for a markdown log or an Obsidian pane.

Contributing

The bar is stated up front: PRs that make agents actually teach better beat PRs that add more files. Six ground rules hold the repo together:

  • One home per fact. Philosophy lives in philosophy.md, process in process.md, quiz tools in quiz-ui.md. Point at those files; don't restate them.
  • Native quiz UI only. No markdown A/B/C/D, ever — not even as a fallback.
  • Don't leak the answer. No (Recommended) on the right option.
  • Struggle stays in the material. Skills absorb logistics only.
  • Portable frontmatter. Agent Skills spec only: name, description, optional license / metadata. name must match the folder; description ≤ 1024 chars and must carry trigger phrases.
  • Keep skills short. Detail goes in references/ one level under the skill. No nested reference chains.

New skills are held to a narrow test: if it isn't part of probe → plan → teach (or visual / verify / profile), ask first. Extra skills that never get invoked are noise.

Maintainer checklist before merging: quiz picker opens, probe writes a map, the plan is a mermaid DAG before teaching, teaching is one node then a lock-in quiz, and no citation is invented.
